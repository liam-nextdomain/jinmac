# kb/raw: 외부 원자료

여기 있는 파일은 **증거**다. JinMac이 쓴 글이 아니라 바깥에서 온 것을 그대로 옮겨 둔 것이다.
`kb/wiki/`의 문서가 이 자료를 해석하고 요약한다.

지금은 요구사항 초안 원문 한 편만 들어와 있다.

## 무엇이 여기로 오는가

| 하위 폴더 | 내용 | 예 |
|---|---|---|
| `references/` | 외부에서 받은 문서와 문헌에서 옮겨 온 부분 | 요구사항 초안 원문, Apple 문서 발췌, Stats 앱의 SMC 키 목록 |
| `probes/` | 0단계 검증 스크립트의 출력 그대로 | SMC 온도 키, IOReport 채널, Foundation Models 가용성 |
| `checkups/` | 실제 기기에서 돌린 검진의 리포트 JSON | 본인 기기 7일 검진 결과 |
| `reports/` | 사용자가 이슈로 알려 온 판정 오류 | "메모리 여유로 나왔는데 실제로는 느렸다" |

요구사항 12장과 14장이 0단계에서 확인할 항목을 적어 두었다. 그것들을 확인하면 출력이
`probes/`로 온다.

## 규칙

**한 번 쓰면 고치지 않는다.** 원자료를 다듬으면 그건 더 이상 증거가 아니다. 해석은
`kb/wiki/`에서 한다. 측정이 틀렸다고 판단되면 새 파일을 추가하고 위키 쪽에서 두 결과를
비교해 설명한다.

**frontmatter를 쓰지 않는다.** `kb/raw/`는 지식 그래프에 들어가지 않는다. 대신 파일 맨 위에
출처 헤더를 둔다.

```markdown
# M5 MacBook Air의 SMC 온도 키

**Source:** swift scripts/probe-smc.swift
**Collected:** 2026-09-20
**Published:** N/A (직접 측정)
**Machine:** Mac17,2, Apple M5, macOS 27.2
```

**파일 이름은 `YYYY-MM-DD-설명.md`.** 소문자 kebab-case, 60자 이내. 발행일을 모르는 문헌은
날짜를 빼고 헤더의 `Published`를 `Unknown`으로 둔다.

**검진 원시 데이터를 넣지 않는다.** 샘플 DB와 CSV에는 그 기기에서 쓴 앱의 번들 ID와 프로세스
이름이 시간순으로 남는다. `checkups/`에는 리포트 JSON만 넣는다. 파일 경로와 사용자 이름은
`~/`와 합성 이름으로 바꾼다. "데이터 외부 전송 0건"은 JinMac이 사용자에게 한 약속인데, 공개
저장소의 지식 베이스가 그 약속이 새는 자리가 되면 안 된다.

## 인용하는 법

`kb/wiki/`의 문서는 본문 머리에서 원자료를 가리킨다. 경로는 그 문서 기준 상대 경로다.

```markdown
> Raw: [2026-09-17-requirements-draft.md](../../raw/references/2026-09-17-requirements-draft.md)
```
